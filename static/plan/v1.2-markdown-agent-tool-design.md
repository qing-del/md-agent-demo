# Markdown Agent Tool v1.2 设计

## 目标

基于现有 Markdown SDK，为 Agent 提供 Markdown 文档读取和替换提案能力。

Agent 使用 `documentId` 定位文章，先读取目录和章节内容；需要修改时创建待确认提案，由前端或 API 确认后执行替换。

## Agent Tool 定义

```java
String getArticleOverview(long documentId);

String getSectionPreview(long documentId, int nodeNumber);

SectionPage getSectionContent(
        long documentId,
        int nodeNumber,
        String cursor);

SectionReplaceProposal proposeSectionReplace(
        long documentId,
        int nodeNumber,
        String originalText,
        String newText);
```

所有 Tool 对外使用数据库中的 `long documentId`，内部转换为 SDK 的 `DocumentId`。

### `getArticleOverview`

读取 Markdown 文章的标题节点树。

- `documentId`：文章 ID。
- 返回带节点编号和层级缩进的标题树。
- 节点编号用于后续章节读取和替换提案。
- 不返回完整正文。

### `getSectionPreview`

读取指定章节的预览信息。

- `documentId`：文章 ID。
- `nodeNumber`：章节节点编号。
- 返回当前标题、直属正文和直属子标题。
- 子章节存在正文或后代节点时追加 `...`。
- 不递归展开孙级章节。

### `getSectionContent`

分页读取指定章节的完整内容。

- `documentId`：文章 ID。
- `nodeNumber`：章节节点编号。
- `cursor`：可选；为空时读取第一页。
- 返回 `SectionPage`：

```text
SectionPage
├── String content
├── boolean hasMore
└── String nextCursor
```

- `nextCursor` 不为空时，Agent 继续调用本 Tool 获取下一页。
- `nextCursor` 是是否继续读取的权威标志；`hasMore` 必须与之保持一致。
- 分页按 UTF-8 字节计算，单页上限为 5120 字节。
- 章节范围包括当前标题、直属正文和所有后代章节。
- `...` 仅表示当前页后仍有内容，不属于原始 Markdown。
- 读取完整章节时必须使用带 cursor 的分页接口，不能把 `...` 拼接回原文。

### `proposeSectionReplace`

创建 Markdown 替换提案。

- `documentId`：文章 ID。
- `nodeNumber`：目标章节节点编号。
- `originalText`：需要被替换的原始文本，不能为空。
- `newText`：替换后的文本，允许为空，表示删除。
- 只允许修改目标章节的直属正文，不修改标题和子章节正文。
- Tool 只创建 `PENDING` 状态的提案，不直接修改文档。
- 返回 `SectionReplaceProposal`：

```text
SectionReplaceProposal
├── String opId
├── long documentId
├── int nodeNumber
├── String originalText
├── String newText
└── OperationStatus status
```

`originalText` 的存在性和唯一性在实际确认执行时再次校验。

## 替换与确认流程

```text
Agent 调用读取 Tool
→ Agent 调用 proposeSectionReplace
→ 后端保存 PENDING 提案并返回 opId
→ 前端展示原文和新文
→ 用户确认 yes / no
→ yes：调用 confirm(opId)，执行 replace 并持久化
→ no：调用 cancel(opId)，不修改 Markdown
```

实际替换继续复用现有方法：

```java
OperationManager.create(...);
OperationManager.confirm(opId);
OperationManager.cancel(opId);
MarkdownManager.replace(...);
```

确认和取消不作为 Agent Tool，由前端或应用 API 完成。Agent 不直接调用 `MarkdownManager.replace`，避免绕过用户确认修改文档。

## 上下文与持久化

- Tool 首次访问文档时，根据 `documentId` 从 `md_documents` 加载正文并注册 Markdown 上下文。
- 文档上传成功后刷新对应上下文。
- 文档删除成功后移除对应上下文。
- `replace` 成功后重新解析 Markdown，生成新的节点编号和 `revision`。
- 替换结果通过 `MarkdownStore` 按 `documentId` 更新现有文档正文和 UTF-8 字节数。
- 替换提案暂存在内存中，应用重启后失效。

## 约束

- 文档不存在、章节不存在或 cursor 非法时返回明确错误。
- 原文不存在或在目标直属正文中匹配多次时，替换失败且 Markdown 不变。
- 数据库持久化失败时，内存上下文保留旧版本。
- 同一 `opId` 只能确认或取消一次。
- v1.2 暂不处理 revision 校验；文档发生变化后，前端应重新获取目录和章节内容。
- v1.2 不提供历史版本恢复和撤销能力。

## 审计日志

- 使用 SLF4J API 和 Spring Boot 默认 Logback 实现，不切换日志框架。
- 使用 Spring AI Observation 记录 Tool 输入、返回值和执行状态。
- 记录每次发送给 LLM 的完整 Prompt 上下文，保留消息顺序、角色、Tool Call 和 Tool Response。
- 使用 `interactionId` 和 `conversationId` 关联同一轮 Agent 调用。
- 日志输出失败不能影响模型调用或 Tool 执行；不记录 API Key、Authorization Header 等凭证。

## 验证场景

- Agent 能通过文章概览获取有效的 `nodeNumber`。
- Agent 能通过 `nextCursor` 连续读取完整章节，内容无丢失、无重复。
- 错误的 `documentId`、`nodeNumber` 或 cursor 能被拒绝。
- 创建替换提案后，原文保持不变，操作状态为 `PENDING`。
- 用户确认后只替换直属正文中的唯一匹配文本。
- 原文不存在或匹配多次时，操作进入 `FAILED`，Markdown 不变。
- 用户取消提案后，操作进入 `CANCELLED`，Markdown 不变。
- 数据库持久化失败时，操作进入 `FAILED`，旧上下文仍可读取。
- 同一 `opId` 不能重复确认或取消。
- 替换成功后，重新读取目录和章节可以看到最新内容。
