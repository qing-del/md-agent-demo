# Markdown AST Tool 设计

## 目标

将一段 Markdown 文本解析为可按 UUID 管理的章节树，支持目录查询、节点预览、分页读取，以及经前端确认后的文本替换与持久化。

## 数据结构

每个 UUID 对应一份不可变的 Markdown 上下文：

```java
MarkdownContext
├── UUID key
├── String revision
├── String source
├── List<Integer> rootNodeIds
└── Map<Integer, SectionNode> nodes
```

标题节点保存：

```java
SectionNode
├── int number
├── int level
├── String title
├── List<Integer> children
├── int headingStart
├── int bodyStart
├── int directEnd
└── int sectionEnd
```

- `number` 按标题在原文中的出现顺序从 1 开始，在当前 Markdown 快照内唯一。
- `source` 保存完整原始 Markdown；节点只保存位置索引，不再维护正文 Map。
- `rootNodeIds` 和 `children` 按原文顺序保存节点编号。
- 节点位置采用 Java String 索引（UTF-16），范围统一左闭右开，与分页使用的 UTF-8 字节偏移区分。
- 原始标题范围为 `[headingStart, bodyStart)`，直接正文范围为 `[bodyStart, directEnd)`，章节及全部后代范围为 `[headingStart, sectionEnd)`。
- `directEnd` 为下一个纳入目录的标题起点；`sectionEnd` 为下一个同级或更高级标题起点；不存在时取文末位置。
- 首个标题之前的文本保留在 `source` 中；没有标题时，节点集合为空，原文仍完整保留。
- `revision` 标识当前快照，刷新内容时更新；首发暂不进行版本一致性校验。
- 上下文通过 `Map<UUID, MarkdownContext>` 管理；重新解析相同 UUID 时整体替换旧快照。

## 解析规则

构造时传入 `UUID key` 和 `String source`，使用 `commonmark-java` 解析 Markdown，开启 `IncludeSourceSpans.BLOCKS` 获取原文位置。

从 AST 中提取文档顶层的标题节点，再使用栈按照标题等级建立章节树：父节点为前方最近的较低等级标题，允许标题跳级。引用块、列表中的标题不纳入目录，代码块中的标题样式文本由解析器识别为代码。

AST 的标题节点本身不包含整节正文；章节范围由标题顺序和等级计算，查询时直接切取原文。

例如：

```text
1. # Java
2. ## 安装
3. ### JDK 安装
4. ## 开发工具
5. # Python
6. ## 安装
```

对应结构：

```text
根节点
├── 1. # Java
│   ├── 2. ## 安装
│   │   └── 3. ### JDK 安装
│   └── 4. ## 开发工具
└── 5. # Python
    └── 6. ## 安装
```

## 节点内容预览

查询指定节点时返回：

1. 当前节点的标题。
2. 当前节点的直接正文。
3. 当前节点的直属子标题，不递归展开孙级节点。
4. 子标题存在直接正文或子节点时，在标题后追加 `...`。

例如查询 `# Java` 节点：

```markdown
# Java
Java 是世界上最伟大的语言
接下来我们讲解如何安装 Java

## 安装 ...
## 开发工具 ...
## 技术栈
```

省略号表示该子标题下仍有可继续查询的内容或结构，由查询时动态生成，不修改原文。

## 接口定义

```java
MarkdownContext getEntity(UUID key);

String getHeadingTree(UUID key);

String getSectionPreview(UUID key, int nodeNumber);

String getSectionAll(UUID key, int nodeNumber);

SectionPage getSectionAll(UUID key, int nodeNumber, String cursor);

ReplaceResult replace(SectionNodeRef section, String originalText, String newText);
```

- `getEntity`：获取 UUID 对应的完整 Markdown 上下文实体。
- `getHeadingTree`：获取带节点编号的标题目录树。
- `getSectionPreview`：获取指定编号节点的正文及折叠后的直属子标题。
- `getSectionAll`：读取指定节点的标题、直接正文和全部后代内容；无 cursor 的简化接口返回第一页文本，有 cursor 的接口返回分页结果。
- `replace`：在指定节点的直接正文内执行原始 Markdown 精确替换，不包含标题及后代章节。`SectionNodeRef` 包含文档 UUID 和节点编号。

## cursor 与字节分页

- 按待读取章节的 UTF-8 字节序列分页，5 KB 定义为 5120 字节；cursor 偏移相对于该章节起点。
- 页码从 0 开始：第 0 页名义范围为 `[0, 5120)`，第 1 页为 `[5120, 10240)`，以此类推。
- UTF-8 多字节字符不能拆开返回。遇到边界落在字符内部时，当前页结束位置回退至完整字符边界，下一页从实际结束位置继续，保证不丢字、不重复。后续页按实际偏移继续取最多 5120 字节，因此含多字节字符时不保证严格按页码乘 5120 定位。
- 为维持原有的 5 KB 文本上限，未读完时在预算内预留末尾 `...` 的 3 字节；标记不属于原文，不能计入下一页的原文偏移。上述范围为名义窗口，实际读取量受字符边界及省略标记影响。
- `SectionPage` 返回 `content`、`hasMore`、`nextCursor`；读完时 `hasMore=false`、`nextCursor=null`。分页元数据不计入正文文本的 5 KB 上限。
- cursor 由业务层管理，包含文档 UUID、节点编号和下一页实际 UTF-8 字节偏移；`commonmark-java` 只提供解析及原文位置，不提供此分页协议。
- 分页不重新渲染 Markdown，也不保证单页代码块或其他 Markdown 结构完整闭合。

## 替换与前端确认

首发不允许人为修改文本，暂不处理版本不一致及跨编辑 cursor 迁移。内容刷新后，前端重新获取目录并从第一页读取。

流程：

```text
前端发起请求 → 后端 LLM 生成替换提案
→ 后端通过 OperationLog 保存待确认操作，并返回结果及 UUID 类型的 OpId
→ 前端选择 yes / no，并携带 OpId 发起确认请求
→ yes：执行 replace，重新解析节点树，写入 DB 并刷新上下文
→ no：取消待确认操作，不修改内容
```

- 文档 `key` 标识 Markdown 上下文；`OpId` 标识一次待确认操作，两者用途不同。
- 待确认操作保存目标节点引用、`originalText`、`newText` 和操作状态；LLM 阶段只生成提案，不直接执行替换。
- `originalText` 非空且必须在目标范围内唯一匹配；未找到或匹配不唯一时返回失败。`newText` 可为空，表示删除匹配片段。
- 替换原文后重新解析完整文档，生成新的节点编号、位置索引及 `revision`，不手动平移旧节点偏移。
- DB 写入成功后发布新上下文；写入失败时保留旧上下文并返回失败。已完成或取消的 OpId 不得重复执行替换。

### 待确认操作管理

`OperationLog` 专门管理操作的临时状态，内部使用 `Map<UUID, Operation>`，以 `OpId` 为 key；并发实现采用 `ConcurrentHashMap`。

```text
Operation
├── UUID opId
├── SectionNodeRef section
├── String originalText
├── String newText
└── OperationStatus status
```

- `OperationLog` 提供创建、按 OpId 查询、确认执行和取消入口；新操作状态为 `PENDING`（待确认）。
- `yes` 原子地将 `PENDING` 改为 `EXECUTING`，再执行替换与持久化；成功标记 `COMPLETED`，失败标记 `FAILED`。
- `no` 仅允许将 `PENDING` 改为 `CANCELLED`。同一 OpId 只能离开待确认状态一次，避免并发确认或重复请求导致重复替换；仅使用并发 Map 不足以保证状态转换原子性。
- 首发仅在后端内存中暂存操作，不作为持久化审计日志；服务重启后待确认操作失效。查询不到 OpId 时返回操作不存在或已失效。
